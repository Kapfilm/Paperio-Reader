## Where we are

We pivoted the Stage-1 direction. The old Increment E/F approach (content.bin bolted onto
the reader via a tee + read-back) was **reverted** — device diagnostics proved it never
engaged and regressed the reader with heap-fragmentation OOM ("empty chapter"). The new
target follows **microreader's model**: content.bin becomes the single conclusive book
cache, read **live one page at a time** from a cursor; section files get deleted. Enriched
with our two differentiators: **background compilation** (fast first page) and **arena
memory** (kills the fragmentation that broke F).

Full design + rationale: [docs/stage1-single-source-live-pagination-2026-07-27.md](stage1-single-source-live-pagination-2026-07-27.md).

## G1 in detail (done)

content.bin v7: each spine's aux region gains a block-offset table (written after the chapter
table in `ContentBinWriter::onSpineEnd`): `blockCount × BlockOffset{fileOffset, charOffset,
recordIndex}`, **one entry per LOGICAL block** (kContinuation split records share their base
block's entry).

- `BlockOffset` struct: [CompiledContent.h](../lib/Epub/Epub/content/CompiledContent.h) (near
  Anchor/PageBreakLabel). `kVersion = 7`.
- Serializers `write/readBlockOffsets`:
  [BlockSerialization.{h,cpp}](../lib/Epub/Epub/content/BlockSerialization.cpp) (mirror the
  anchor pattern).
- Writer: [ContentBinWriter.cpp](../lib/Epub/Epub/content/ContentBinWriter.cpp) — `blockOffsets_`
  member, captured at each `onBlock` (position + charOffset + running record count), cleared in
  `beginSpineAt`, written in `onSpineEnd`.
- Reader: [BlockStreamReader.{h,cpp}](../lib/Epub/Epub/content/BlockStreamReader.cpp) —
  `spineBlockOffsets_` loaded in `openSpine`; new `seekToBlock(i)`.
- **Why `recordIndex` is in the struct**: anchors/labels/chapters are keyed on the **record**
  index (writer's `blockCount_` counts records, not logical blocks). `seekToBlock` restores
  `currentFirstRecordIndex_` from it so the `replaySpine` cross-reference in `LayoutSink`
  (LayoutSink.cpp ~L889) keeps resolving after a seek.
- Test: `ContentBinStream.SeekToBlockMatchesSequentialRead` — seek(N)+forward read == sequential
  read from N (text, record index, char offset); out-of-range rejected.

## NEXT: G2 — LayoutSink one-page-from-cursor mode

**Goal**: lay out exactly ONE page starting at a `PagePosition {blockIndex, wordOffset}`,
report the end position; backward layout for prev_page. This is the crux of the read-path shift.

- Today `LayoutSink` paginates a **whole spine** to completion, emitting every page via
  `completePageFn` ([LayoutSink.h](../lib/Epub/Epub/content/LayoutSink.h);
  `makePages`/`addLineToPage`/`emitPage` in the .cpp). The internals (measure/wrap/image/table/
  float) are reused verbatim.
- The driver is `replaySpine` / `replaySpineStep` (BlockStreamReader.cpp / declared in
  BlockStreamReader.h). It feeds blocks via `nextLogicalBlock` and cross-refs anchors on
  `currentFirstRecordIndex()`.
- **Approach**: use G1's `seekToBlock(blockIndex)` to start replay mid-spine; add a one-page
  stop condition to LayoutSink (emit one page, capture end `{blockIndex, wordOffset}`, halt);
  add backward layout (microreader's `layout_backward` in scratchpad/mr/TextLayout.cpp is the
  reference).
- **Host test**: page K laid out from cursor == page K from a full whole-spine run
  (position-identical). The existing whole-spine pagination is the oracle.

## Design invariants to preserve (do not violate)

- **NO tee.** The v2 plan and Fable's review rejected it: `LayoutSink::abbreviatePreviewRuns`
  mutates the block in place, so a tee feeding LayoutSink leaks settings-dependent data into
  content.bin, invisible to byte-identical gates. The background compile uses the content-only
  `setStage1Sink`, which already exists and is correct.
- **Background compile + fast first page is a design principle** (user, explicit). First page
  never gated on content.bin.
- **Device is `-fno-exceptions`**: no try/catch, no throwing `operator new`. Use
  `makeUniqueNoThrow` (lib/Memory). This is why F's OOM aborted.
- **No whole-file reads** (user, explicit): stream everything on device.
- **content.bin is a rebuildable cache**: a version/fingerprint mismatch just recompiles — that
  is why the v7 bump needs no migration.
- **Cadence agreed for this sequence**: run G1→G3 host-green, then **hard-stop at G4** for the
  user to flash + measure.
