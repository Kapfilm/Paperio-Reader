## The architecture (settled — no open design questions for the engine)

Comparing microreader's `TextLayout` to our `LayoutSink` showed they're opposite architectures.
`TextLayout` is a PURE `layout(cursor) → one Page` / `layout_backward(cursor)` function built from
a per-paragraph line cache + symmetric `collect`/`collect_backward`, with alignment as a decoupled
per-line post-pass (the RTL seam). `LayoutSink` is a stateful streaming sink that emits pages as a
side effect, alignment woven into the page state machine. **Decision: build the pull core, retire
LayoutSink's pagination role** (reuse its per-paragraph measure/wrap + block-style resolution).

**Cursor** (`compiled::PagePosition`): `{spineIndex, blockIndex, offset, charOffset, auxFontId,
imageCounter}`. `offset` is polymorphic by block type — line index (text), pixel row (page-split
image), row index (table) — exactly microreader's overloaded `offset`. Two spine-scoped scalars
are carried because they're NOT reconstructible from a local window: `auxFontId` (heading aux-font
latch) and `imageCounter` (image-cache-path counter).

**Cross-block restart-boundary result** (the algorithm-defining audit, `dfa45176`): `emitPage`
resets ALL pixel-affecting cross-block accumulators, and floats provably never cross a page
boundary — so laying out the page starting at a block boundary with a zeroed cursor is
pixel-correct, with two caveats: (A) rebuild the empty-block/`<br>` margin-collapse chain by
replaying only the trailing empty-block run (bounded), and (B) `auxFontId` is the one unbounded
latch → carried in the cursor. Multi-page tables (`d3c97de5`) don't break this: a table is one
block, row-packed into independent per-page fragments, only `currentPageNextY_` crosses (and
`emitPage` zeroes it).

## G2a done (the scaffold)

[PageLayout.{h,cpp}](../lib/Epub/Epub/content/PageLayout.cpp): `layoutPage(reader, renderer,
params, startCursor)` seekToBlock()s the cursor's block (G1) and drives the trusted LayoutSink for
exactly one page (captures the first `completePageFn`, stops). Since a valid cursor is a page
boundary, LayoutSink's first emitted page is exactly the requested page. End cursor is
block-granular in G2a. Oracle [PageLayoutTest.cpp](../test/epub_pipeline/PageLayoutTest.cpp):
pull-core first page == whole-spine `replaySpine` golden's first page, corpus × 3 profiles, all
spines. This pinned the cursor type, `seekToBlock`, and the position-identical rig with zero
layout-behavior risk.

## NEXT: G2b+G3 merged — build the PURE collect() core

**Decided 2026-07-27**: G2b needs precise intra-block end cursors + mid-block resume + backward
layout. Microreader gets all three free from OWNING the collect loop
(`collect_page_items` TextLayout.cpp:1250 — `break_idx` = end offset, `start_idx = pos.offset` =
mid-block resume; `collect_page_items_backward` :1406). Extracting them from the streaming
LayoutSink is invasive surgery, so **G2b is where the pure core replaces the scaffold**, and its
per-paragraph laid-out cache IS G3's cache — the two steps merge.

Build in `PageLayout.{h,cpp}` (keep the `PagePosition`/`LaidOutPage` interface + the oracle test):
- OWN the collect loop. Per-block laid-out cache (ring, key = blockIndex, holds the wrapped
  `TextBlock` lines + per-line heights; invalidate on any `LayoutParams` change).
- Reuse `ParsedText::layoutAndExtractLines` (ParsedText.h:118) for line-breaking +
  `buildBlockStyle`/`resolveBlockFont` (LayoutSink.cpp:95/55). Do NOT reuse LayoutSink pagination.
- `collect_fwd(cursor) → items + precise boundary` (mirror `collect_page_items`);
  `collect_bwd(end) → backward page` (mirror `collect_page_items_backward` + `collect_backward`).
- Block-type dispatch must mirror `LayoutSink::onBlock` (LayoutSink.cpp:726+): Image →
  placeBlockImage, Hr → placeHr, Table → row-packed fragments (`offset` = row), Text → lines.
  Handle the cross-block caveats (empty-block lookback; `auxFontId`/`imageCounter` carried).
- Oracle extends: page K from page-K-start cursor == golden page K (ALL pages) +
  `layout_backward`(page K+1 start) == page K, corpus × profiles.
- Arena-backing the cache/lines is the memory-home decision at G5 (reader wiring); the host core
  can use heap. On device, `TextBlock` lines were THE fragmentation driver — arena them when wiring.

## Invariants (do not violate)

- **NO tee** (leaks settings-dependent data into content.bin; use content-only `setStage1Sink`).
- **Fast first page** is a design principle — never gate page 1 on content.bin.
- **RTL is near-term** — keep alignment a per-line post-pass (mirror word-x, reverse BiDi runs),
  never fused into the collect/page-break loop.
- Device is **`-fno-exceptions`**: no try/catch, no throwing `new`; use `makeUniqueNoThrow`.
- **No whole-file reads** on device; stream.
- content.bin is a **rebuildable cache**: version/fingerprint mismatch → recompile (why v7 needs no
  migration).
